## Overview

The calendar page lives at `/calendar` and is rendered by `src/app/(admin)/(others-pages)/calendar/page.tsx`. It mounts the `Calendar` client component and wraps it with a `PageBreadcrumb` for consistent navigation context.

```tsx
// src/app/(admin)/(others-pages)/calendar/page.tsx
import Calendar from "@/components/calendar/Calendar";
import PageBreadcrumb from "@/components/common/PageBreadCrumb";
import { Metadata } from "next";

export const metadata: Metadata = {
  title: "Next.js Calender | TailAdmin - Next.js Dashboard Template",
  description:
    "This is Next.js Calender page for TailAdmin Tailwind CSS Admin Dashboard Template",
};

export default function page() {
  return (
    <div>
      <PageBreadcrumb pageTitle="Calendar" />
      <Calendar />
    </div>
  );
}
```

## FullCalendar Integration

The `Calendar` component (`src/components/calendar/Calendar.tsx`) uses **FullCalendar v6** with three plugins:

| Package | Purpose |
|---|---|
| `@fullcalendar/react` | React wrapper for FullCalendar |
| `@fullcalendar/daygrid` | Month and day-grid views |
| `@fullcalendar/timegrid` | Week and day time-grid views |
| `@fullcalendar/interaction` | Click and drag-to-select interactions |

The component is marked `"use client"` so it only runs in the browser — FullCalendar does not support SSR.

---

## Calendar Configuration

```tsx
// src/components/calendar/Calendar.tsx
<FullCalendar
  ref={calendarRef}
  plugins={[dayGridPlugin, timeGridPlugin, interactionPlugin]}
  initialView="dayGridMonth"
  headerToolbar={{
    left: "prev,next addEventButton",
    center: "title",
    right: "dayGridMonth,timeGridWeek,timeGridDay",
  }}
  events={events}
  selectable={true}
  select={handleDateSelect}
  eventClick={handleEventClick}
  eventContent={renderEventContent}
  customButtons={{
    addEventButton: {
      text: "Add Event +",
      click: openModal,
    },
  }}
/>
```

| Option | Value | Effect |
|---|---|---|
| `initialView` | `dayGridMonth` | Opens in month view |
| `selectable` | `true` | Click-drag to select a date range |
| `select` | `handleDateSelect` | Opens the add-event modal pre-filled with the selected dates |
| `eventClick` | `handleEventClick` | Opens the edit-event modal for an existing event |
| `customButtons` | `addEventButton` | Adds an "Add Event +" button to the toolbar |

## Event Data Model

Events are stored in React state as an array of `CalendarEvent` objects that extend FullCalendar's `EventInput` interface:

```tsx
interface CalendarEvent extends EventInput {
  extendedProps: {
    calendar: string; // "Danger" | "Success" | "Primary" | "Warning"
  };
}
```

Three seed events are initialised on mount:

```tsx
useEffect(() => {
  setEvents([
    {
      id: "1",
      title: "Event Conf.",
      start: new Date().toISOString().split("T")[0],
      extendedProps: { calendar: "Danger" },
    },
    {
      id: "2",
      title: "Meeting",
      start: new Date(Date.now() + 86400000).toISOString().split("T")[0],
      extendedProps: { calendar: "Success" },
    },
    {
      id: "3",
      title: "Workshop",
      start: new Date(Date.now() + 172800000).toISOString().split("T")[0],
      end: new Date(Date.now() + 259200000).toISOString().split("T")[0],
      extendedProps: { calendar: "Primary" },
    },
  ]);
}, []);
```

## Event Colours

Events are colour-coded using a `calendar` extended property. The four levels map to Tailwind CSS classes:

```tsx
const calendarsEvents = {
  Danger:  "danger",
  Success: "success",
  Primary: "primary",
  Warning: "warning",
};
```

The custom `renderEventContent` function applies the colour as a CSS class:

```tsx
const renderEventContent = (eventInfo: EventContentArg) => {
  const colorClass = `fc-bg-${eventInfo.event.extendedProps.calendar.toLowerCase()}`;
  return (
    <div className={`event-fc-color flex fc-event-main ${colorClass} p-1 rounded-sm`}>
      <div className="fc-daygrid-event-dot"></div>
      <div className="fc-event-time">{eventInfo.timeText}</div>
      <div className="fc-event-title">{eventInfo.event.title}</div>
    </div>
  );
};
```

## Add / Edit Event Modal

Both adding and editing events use the same modal, driven by the `useModal` hook. When `selectedEvent` is `null` the modal is in *add* mode; when it holds an event it switches to *edit* mode.

**Modal form fields:**

| Field | Type | Notes |
|---|---|---|
| Event Title | `text` | Controlled via `eventTitle` state |
| Event Color | radio group | Maps to `Danger`, `Success`, `Primary`, `Warning` |
| Start Date | `date` | Controlled via `eventStartDate` state |
| End Date | `date` | Controlled via `eventEndDate` state |

```tsx
// Add or update logic
const handleAddOrUpdateEvent = () => {
  if (selectedEvent) {
    // Update existing event in the events array
    setEvents((prev) =>
      prev.map((e) =>
        e.id === selectedEvent.id
          ? { ...e, title: eventTitle, start: eventStartDate,
              end: eventEndDate, extendedProps: { calendar: eventLevel } }
          : e
      )
    );
  } else {
    // Append a new event
    const newEvent: CalendarEvent = {
      id: Date.now().toString(),
      title: eventTitle,
      start: eventStartDate,
      end: eventEndDate,
      allDay: true,
      extendedProps: { calendar: eventLevel },
    };
    setEvents((prev) => [...prev, newEvent]);
  }
  closeModal();
  resetModalFields();
};
```

## Persisting Events

By default events are held in local React state and reset on page refresh. To persist them:

<Steps>
  <Step title="Fetch initial events from an API">
    Replace the `useEffect` seed data with a fetch call to your events endpoint. Map the API response to the `CalendarEvent` interface before calling `setEvents()`.
  </Step>
  <Step title="Save new events">
    Inside `handleAddOrUpdateEvent`, POST the new event object to your API before (or after) updating local state.
  </Step>
  <Step title="Delete events">
    Add a delete button to the edit modal. Call your DELETE endpoint, then filter the event out of the `events` array with `setEvents(prev => prev.filter(e => e.id !== selectedEvent.id))`.
  </Step>
</Steps>

<Note>
  FullCalendar's `events` prop also accepts a URL string or a function callback for server-side event fetching. See the FullCalendar docs for `EventSource` options if you prefer to let FullCalendar manage the fetch lifecycle.
</Note>
